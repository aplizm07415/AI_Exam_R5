# R4

中小企業診断士一次試験のうち、財務・会計、運営管理、経営法務、中小企業経営・中小企業政策を各80点まで段階的に仕上げる個人学習アプリです。

## 収録内容

- Azure `example-resource` 由来の4科目問題データ: 2,463問（完全重複1問を除外）
- 2026年版中小企業白書の公的出典付き補充問題: 12問
- アプリ収録数: 2,474問
- GitHub側のtaxonomy: 388論点
- 60点・70点・80点別 study plan
- 令和8年度（2026年度）公式問題PDFと公式正解・配点
- 誤答、見直し、メモ、論点別正答率、公式模試結果の保存
- 本試験までの日数、今日の残り問題数、7日間の学習量、フェーズ日程・達成項目をまとめたダッシュボード
- 日商簿記2級、一次財務、二次事例Ⅳを接続する財務ルートと節目管理
- 60点基礎層・70点追加層・80点追加層を重複なく集計する層別進捗
- 60点基礎層1,483問を「基礎・定着・判定」の3チェックポイントへ分割し、4科目均等の達成条件で段階開放
- 下位層を含む累積到達判定と、未合格時の上位層グレーロック
- 正答率・直近安定率・実施セッション数から判定する厳しめの自動チェック
- 日程遅延を残日数へ分散し、科目配分込みで本日の問題数を調整する自動割当
- 通常演習・復習・公式模試の全セッション履歴と、セッション単位の削除・再集計
- Neonでは現在状態とセッション履歴を分離し、変更セッションだけを差分保存（旧JSONは初回読込時に自動移行）
- 全フェーズの日程・項目達成・実施量・現在地をまとめる全体確認ページ
- 全体確認からフェーズ開始・終了日と学習除外日を一元管理し、予定量・遅延補正・自動割当・予実グラフへ共通反映
- Phase 1開始前（2026年8月17〜23日）の事前学習を実績へ加算し、予定線との差を数値とグラフで表示
- 正解済み問題のアーカイブと復元、選択肢の除外表示、計算問題用の初期最小化電卓
- 全解説を「まず→次に→最後に」の思考順序へ統一し、正答再掲・難易度・注意点・区切り見出しを非表示
- 全2,474問の採点後解説を、条件・判断手順・科目別図解・正答・元解説で構成する順序型レイアウトに統一
- 現行制度・計算不整合など60問を修正し、公的出典URLを解説から直接開ける表示

通常演習の正答と解説はブラウザへ一括配信せず、1問ごとにサーバーで採点します。問題一覧も必要なセッション分だけ取得するため、2,474問を一度にダウンロードしません。

## ローカル起動

Node.js 20以上を使用します。

```bash
npm install
npm test
npm run audit:data
npm start
```

`http://127.0.0.1:4173` を開きます。`DATABASE_URL` が未設定の場合、学習記録はブラウザのLocalStorageへ保存されます。

## データ構成

```text
content/
├── exam.json                 R4設定、4科目、段階学習スケジュール
├── source/                   Azureからコピーした原本4ファイル
├── analysis/                 taxonomy、study plan、構造化済み計画
├── official/                 令和8年度の公式模試・正解・論点分析
├── supplemental/             公的資料に基づく補充問題
├── corrections.json          原本を保持したまま適用する訂正
├── exclusions.json           重複等の除外記録
└── question-index.json       原本2,463問とtaxonomyの対応、難易度、コース
```

`tools/build-r4-content.js` は、ルートのtaxonomy・study planとAzure原本から索引を再生成します。難易度は解説の長さではなく、判断数、条件分岐、計算工程、補完知識から判定します。`tools/audit-questions.js` は正答ID、選択肢重複、空解説、文字化け、更新対象などを全件検査します。`tools/extract-r8-answers.py` は公式正解PDFからマークシート定義を再生成する保守用ツールです。

## Vercel + Neon

1. GitHubリポジトリをVercelへImportします。
2. Root Directoryを `exam-app-template` にします。
3. Framework Presetは `Other`、Build Commandは空欄のままにします。
4. Neonを接続し、Vercelの環境変数へ `DATABASE_URL` を設定します。
5. 個人識別子として `APP_USER_ID` を設定します（例: `owner`）。
6. デプロイ後に `/api/health` を開き、`questionCount: 2474` と `database: configured` を確認します。

Neonでは初回アクセス時に `exam_states` テーブルを自動作成します。スキーマは `database/001_exam_states.sql` と同じです。

学習状態は次の2表へ保存します。

- `exam_states`: メモ、フラグ、計画、回答選択などの小さなスナップショット
- `exam_session_states`: 通常演習・復習・公式模試を1セッション1行で保存

回答のたびに全履歴を再送せず、変更されたセッションだけを保存します。旧版の `exam_states.state.sessions` は初回読込時に自動分割されます。Postgres/Neonの保存容量を増やすだけではなく、ネットワーク転送量、複数保存の競合、長期運用時のAPI本文サイズを同時に抑える設計です。

公開URLで運用する場合は、固定の `APP_USER_ID` を認証の代用にせず、Vercel Deployment Protectionなどでアプリ自体へのアクセスを制限してください。

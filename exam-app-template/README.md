# R4

中小企業診断士一次試験のうち、財務・会計、運営管理、経営法務、中小企業経営・中小企業政策を各80点まで段階的に仕上げる個人学習アプリです。2027年度向けの計画を持ち、試験日は正式公表前の仮置きとして扱います。

## 収録内容

- 元問題2,463問から完全重複1問を除き、公的出典付きの2026年版白書補充12問を追加した問題バンク2,474問
- 必須図表・条件が不足する22問を隔離し、通常演習対象は2,452問（財務487・運営548・法務489・中小928）
- 2026年9月の重点点検で17問を訂正・改題・公式原図から復元。改題には条件を明記し、元の試験を復元した問題とは区別
- taxonomy 388論点、60点・70点・80点別の学習計画。現在の問題に対応する論点IDは268件で、試験範囲の網羅率とは区別
- 60点基礎層1,775問、70点追加層365問、80点追加層312問。60点層を3チェックポイントに分け、4科目の条件を満たすと上位層を開放
- 令和8年度（2026年度）公式問題PDF、正解・配点、タイマーと答案入力
- 日商簿記2級・一次財務・二次事例Ⅳをつなぐ財務ルート、外部教材の学習時間・実施記録
- 週の学習可能時間と、残る3科目の免除確認状況を学習計画から入力・保存

## 学習と記録

通常演習は試行ごとに未選択・解説非表示から始めます。解答、提示時刻、所要時間、初見／既見、教材版を記録し、同じ試行の採点は一度だけ計上します。前の解答・解説確認から24時間未満の再回答は練習履歴に残し、理解度判定には使いません。隔離問題と、訂正で評価対象外になった旧版の成績も判定から除きます。

論点の自動完了は対応問題の成績で判定し、対応教材のない項目を他の論点で代用しません。簿記・事例演習などの実施項目は、教材名・日付・時間と完了条件の自己申告を保存します。一次の80点確認はこれらと分け、初見・時間内・電卓なしで80点以上の異なるセットを2つ記録する条件です。通常問題のコース到達度と本試験形式の得点は別の指標で、合格確率を保証するものではありません。

復習は誤答・見直しフラグ・復習期限を使います。初期設定では自力正解の積み重ねに応じて次回を1日・7日・30日後にし、誤答後は1日後へ戻します。3日正解による永久自動除外は廃止し、旧自動アーカイブは復習へ戻します。手動アーカイブは維持します。

日次割当はフェーズ配分と遅れを反映し、当日の既回答IDを除外します。中断した通常演習・日次演習を再開できます。公式模試も答案と期限を保存し、再開時に復元します。一次試験は電卓なしとし、時間終了後は答案を固定して、答案明細と結果を保存します。通常演習の電卓は基礎学習の検算用です。採点前にアプリ内電卓を使った回答は練習として記録し、理解度判定から除外します。

週の学習時間の入力は計画確認用です。現在の問題数配分はフェーズの設定によるもので、入力時間から問題数を自動最適化する機能ではありません。外部の簿記・二次教材は実施記録を残せますが、答案添削・事例Ⅰ〜Ⅲの問題配信は実装していません。

## ローカル起動

Node.js 20以上を使用します。

```bash
npm install
npm test
npm run audit:data
npm start
```

`http://127.0.0.1:4173` を開きます。`DATABASE_URL` が未設定の場合、学習記録はブラウザのLocalStorageへ保存されます。

正答と解説は通常演習の開始時に一括配信せず、問題ごとにサーバーで採点して取得します。問題一覧も必要な範囲をページ単位で取得します。

## データ構成

```text
content/
├── exam.json                 4科目、段階学習スケジュール、財務配分
├── source/                   元問題4ファイル
├── analysis/                 taxonomy、構造化計画、解説補正
├── official/                 令和8年度の公式模試・正解・論点分析
├── supplemental/             公的資料に基づく補充問題
├── corrections.json          原本を保持して適用する訂正
├── exclusions.json           完全重複等の除外記録
├── quality-review.json       確認状態、教材版、評価可能な版、隔離理由
└── question-index.json       元問題と論点・難易度・コースの対応
```

`tools/build-r4-content.js` はtaxonomy・study planから索引を再生成します。`tools/audit-questions.js` は構造、図表依存、複数正答候補、更新候補などを点検します。機械監査に合格しても、全問の専門的内容を確認済みとするものではありません。隔離問題は原資料を確認できるまで出題を止めます。

解説の本文、正答の根拠、式・単位、各選択肢の説明を保持し、一律の3分割や「正解」を含む文の削除は行いません。訂正は原本を書き換えずに適用し、評価に影響する変更には教材版を付けます。

## Vercel + Neon

1. GitHubリポジトリをVercelへImportします。
2. Root Directoryを `exam-app-template`、Framework Presetを `Other` にし、Build Commandは空欄にします。
3. Neonを接続し、Vercelの環境変数へ `DATABASE_URL` を設定します。
4. 個人識別子 `APP_USER_ID` を設定します（例：`owner`）。
5. 公開URLへのアクセスをVercel Deployment Protectionなどで制限します。固定の `APP_USER_ID` は認証ではありません。
6. デプロイ後に `/api/health` で `questionCount: 2452` と `database: configured` を確認します。

初回接続時にスキーマを作成します。`exam_states` はメモ・計画などの状態、`exam_session_states` は演習と模試の試行、`exam_session_deletions` は削除記録を保持します。旧版の一括JSONは読込時にセッションへ分割移行します。

変更したセッションを差分保存し、未送信の変更と削除待ち情報を端末にも永続化します。競合時はセッションID・試行IDで履歴を統合し、サーバーの削除記録を使って削除済みセッションの復活を防ぎます。メモなど同じ項目への同時編集はローカル変更を優先するため、共同編集や版履歴管理の代用にはなりません。

## 保守と残る確認

- 法務・政策は法令の施行日、資料年度、試験の基準日を区別して公的情報と照合します。過年度の統計を問う数値は、その設問の対象年を保ちます。
- 2027年度の正式日程・法令基準日は同年度の公式公表後に確定します。現在の2027年8月7日は仮日程です。
- アプリ内公式模試はR8のみです。設計上のR3〜R8・R5再試験は外部教材で実施記録を残す運用です。
- 隔離22問の原資料回収、未対応論点の教材整備、全問の内容点検、実ブラウザ・実Neonでの運用検証は別途必要です。
- 学習方針は [R4_STUDY_DESIGN.md](docs/R4_STUDY_DESIGN.md)、補充方針は [SUPPLEMENT_PLAN.md](docs/SUPPLEMENT_PLAN.md) を参照してください。
- 今回の修正・検証範囲と次の点検対象は [IMPLEMENTATION_2026-09-06.md](docs/IMPLEMENTATION_2026-09-06.md) にまとめています。
